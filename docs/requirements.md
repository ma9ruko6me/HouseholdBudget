## 1. 概要・目的

本アプリケーションは、マネーフォワード ME のような家計簿Webアプリケーションである。
銀行・カード連携による自動取得は行わず、手動入力を前提としつつ、自分の使いやすい形に
カテゴリ設計や機能をカスタマイズすることを目的とする。

学習課題として、個人利用の家計簿アプリケーションとして開発する。

## 2. 想定利用者・利用シーン

| 項目 | 内容 |
|------|------|
| 主な利用者 | 個人(自分自身の家計管理) |
| 利用シーン | 日々の収支記録、資産(口座・現金・カード)の残高把握、月次の収支振り返り |

## 3. 機能要件

◎＝必須(MVP) ／ ○＝あると良い(後回し可) ／ △＝任意(発展課題)

### 3.1 取引(収支)管理

| 機能 | 優先度 | 内容 |
|------|--------|------|
| 取引の手動登録・編集 | ◎ | 日付・金額・収入/支出区分・カテゴリ・関連資産・メモを持つ取引を登録する。銀行/カード連携・CSV取込は対象外 |
| 取引の削除 | ◎ | 削除ボタン押下時に確認ダイアログを表示し、OKで即時に物理削除する(ゴミ箱・復元機能は持たない) |
| 月別リスト表示 | ◎ | 選択した月の取引を日付順にリスト表示する(メインの一覧形式。カレンダー表示は対象外) |
| 収入の記録 | ◎ | 収入(給与など)は3.2の収入カテゴリを設定して記録する |
| 資産残高調整取引の編集 | ◎ | 3.4の資産残高調整により自動登録された取引は、他の取引と同様に一覧・編集画面から収入/支出区分・カテゴリ・メモを後から編集できる(用途が判明した際に更新するため) |

### 3.2 カテゴリ

| 機能 | 優先度 | 内容 |
|------|--------|------|
| 支出の大カテゴリ(固定) | ◎ | 「固定費」「食費」「生活費」「娯楽費」の4つを固定の大カテゴリとする。大カテゴリ自体の追加・編集・削除は対象外 |
| 支出の中カテゴリ | ◎ | 各大カテゴリの下に中カテゴリを持つ。初期データ(例: 固定費→水道光熱費・家賃など)を用意し、ユーザーが自由に追加・削除できる(取引追加・編集モーダル内のチップ操作で行い、独立したカテゴリ管理画面は持たない。リネーム等の編集機能はスコープ外) |
| 収入カテゴリ | ◎ | 大カテゴリの階層は持たず、「給与」「賞与」「副収入」などのフラットな1階層のカテゴリとする。初期データを用意し、ユーザーが自由に追加・削除できる(支出の中カテゴリと同様、取引追加・編集モーダル内のチップ操作で行う) |

大カテゴリの想定内訳:

| 大カテゴリ | 内容 |
|-----------|------|
| 固定費 | 水道光熱費・家賃など、生活する上で毎月ほぼ同じ額を払う必要がある支出(食費を除く) |
| 食費 | 食費全般 |
| 生活費 | 毎月必ず発生するわけではないが生活する上で必要な支出(日用品・薬・病院代など) |
| 娯楽費 | 映画・動物園・旅行など、自分の娯楽のために使った支出 |

### 3.3 定期取引

| 機能 | 優先度 | 内容 |
|------|--------|------|
| 定期取引の登録 | ◎ | 家賃・サブスクなど毎月発生する取引を登録しておくと、自動的に該当月の取引として登録される |

### 3.4 資産管理

| 機能 | 優先度 | 内容 |
|------|--------|------|
| 資産の登録・編集 | ◎ | 銀行口座・現金・クレジットカードを資産として登録し、残高を管理する(証券・投資等は対象外) |
| 資産別残高表示 | ◎ | 資産ごとの残高、および合計資産額を表示する |
| 取引と資産の紐付け | ◎ | 取引登録時にどの資産(口座・現金・カード)を使ったかを記録し、資産残高に反映する |
| 資産残高調整 | ◎ | 資産一覧画面から実際の残高を入力すると、現在の残高との差額を自動計算し、その差額を「調整」取引として自動登録して資産残高に反映する。調整取引は取引一覧にも表示され、後から用途(収入/支出区分・カテゴリ)を編集できる(3.1参照) |
| 資産間振替 | ◎ | 口座↔口座、口座↔現金、口座↔クレジットカードなど資産間の資金移動を「振替」取引として記録する。カテゴリ選択は不要で、月別収支サマリの収入合計・支出合計には含めない(実質的な収支ではないため) |

### 3.5 分析・レポート

| 機能 | 優先度 | 内容 |
|------|--------|------|
| 月別収支サマリ | ◎ | 選択した月の収入合計・支出合計・収支差額を表示する |
| カテゴリ別集計(グラフ) | ◎ | 選択した月の支出を大カテゴリ別に集計し、グラフ表示する |
| 資産推移(グラフ) | ◎ | 資産全体の残高推移を折れ線グラフで表示する(直近3・6・12ヶ月から期間切替) |

## 4. 非機能要件

| 分類 | 要件 |
|------|------|
| 対応環境 | 主要モダンブラウザ(Chrome, Edge, Safari 最新版)を想定 |
| レスポンシブ対応 | PCでの利用をメインとしつつ、タブレット幅程度までは崩れないレイアウトとする |
| データ永続化 | ページ再読み込み・再訪問後もデータが失われないこと |
| パフォーマンス | 取引数千件程度までは操作にストレスがないこと |
| 保守性 | 学習課題のため、コンポーネント単位で分かりやすく分割されたコードとする |
| データの安全な取り扱い | リポジトリにコミットされるシードデータ・テストフィクスチャ・スクリーンショット等には実際の家計データを含めず、ダミーデータを使用する([CLAUDE.md](../CLAUDE.md)参照) |

## 5. 画面一覧(案)

| 画面名 | 概要 |
|--------|------|
| 取引一覧(月別) | 選択した月の取引をリスト表示し、月別収支サマリ・カテゴリ別支出(ドーナツグラフ)を表示するメイン画面 |
| 取引追加・編集モーダル | 取引の新規登録・編集を行う共通モーダルUI。支出中カテゴリ・収入カテゴリの追加・削除もこの画面のチップ操作で行う |
| 資産一覧 | 登録済みの資産(口座・現金・カード)とその残高、合計資産額を表示する |
| レポート(カテゴリ別集計・資産推移) | 選択した月の支出をカテゴリ別にグラフ表示し、あわせて資産全体の残高推移を表示する |
| 定期取引管理 | 定期取引の登録・編集・削除を行う |

## 6. データ項目(案)

| エンティティ | 主な項目 |
|-------------|---------|
| 取引 | 日付、金額、収入/支出区分、登録種別(通常/資産残高調整)、大カテゴリ(支出のみ)、中カテゴリ(支出時は支出中カテゴリ、収入時は収入カテゴリ)、資産(紐付け)、メモ |
| 資産 | 名称、種別(銀行口座/現金/クレジットカード)、残高 |
| 定期取引 | 金額、大カテゴリ、中カテゴリ、資産、頻度(毎月)、登録日 |
| 支出中カテゴリ | 名称、所属する大カテゴリ |
| 収入カテゴリ | 名称(大カテゴリの階層は持たないフラットな一覧) |

詳細なER図・テーブル定義は基本設計書で確定する。

## 7. スコープ外・将来拡張

- 銀行・クレジットカードのAPI連携による自動取得
- CSV取込によるまとめ登録
- 予算管理機能(カテゴリ別・月別の予算設定と実績比較)
- 証券・投資資産の管理
- 取引のゴミ箱・論理削除・復元機能
- 複数ユーザー対応(共有家計簿など)
